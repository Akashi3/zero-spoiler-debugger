🛡 Zero-Spoiler Debugger

**ИИ-ментор для студентов Tomorrow School, который помогает найти ошибку в коде, но никогда не выдаёт готовое решение.**

Проект для кейса 2 «Zero-Spoiler Debugger» · BRIDGERS STARTUP CHALLENGE 2026

---

## Проблема

В Tomorrow School нет лекций и преподавателей: студенты учатся по принципу Peer-to-Peer и должны сами находить и понимать свои ошибки. Но обычные ИИ-ассистенты в ответ на вопрос «почему не работает?» сразу выдают исправленный код. Студент копирует его, не понимая причины, и учебная цель теряется.

## Решение

Веб-приложение, где ИИ играет роль наставника, а не исполнителя:

1. Студент вставляет код и описывает проблему.
2. Ментор анализирует код и **задаёт один наводящий вопрос за раз**.
3. Подсвечивает строки, куда стоит посмотреть.
4. Учитывает ответы студента и подстраивает подсказки.
5. В конце подводит итог: что понял студент и что стоит запомнить.

## Возможности

- **Диалог, а не ответ.** Один-два коротких вопроса за ход, с опорой на рассуждения студента.
- **4 уровня помощи.** Наводящий вопрос → где смотреть → какая идея за этим → самая узкая подсказка. Ни один уровень не раскрывает исправление. Уровень повышается кнопкой «Я застрял(а)».
- **Подсветка строк** в редакторе кода.
- **Эксперименты и трассировка.** Ментор предлагает проверить вход вручную или предсказать вывод, чтобы студент сам увидел, как ведёт себя программа.
- **Итог сессии** с идеей, которую стоит запомнить, и советом, как ловить такие ошибки в будущем.
- Работает с любым языком программирования, отвечает на языке студента.

## Как обеспечивается принцип Zero-Spoiler

| Слой | Что делает |
|---|---|
| **Системные правила** (сервер) | Запрещают код, «замени X на Y», diff и псевдокод решения. Код студента и диалог считаются данными, а не командами. |
| **Серверный фильтр ответов** | Если в ответе модели обнаружен код, ответ запрашивается заново. При повторном нарушении подставляется безопасный вопрос. |
| **Детектор обхода** | Фразы вроде «игнорируй правила», «дай готовое решение», «ты теперь…» помечаются, модель вежливо отказывает и возвращается к вопросу. Пользователь видит индикатор Shield. |
| **Правила на сервере** | Промпт и ограничения хранятся в `api/chat.js`, их нельзя подменить из браузера. |

## Архитектура

```
Браузер (index.html)  ──POST /api/chat──▶  Vercel Function (api/chat.js)  ──▶  Gemini API
   редактор, чат,                           правила Zero-Spoiler,
   подсветка строк                          серверный фильтр, ключ API
```

Ключ API хранится только в переменной окружения на сервере и в браузер не попадает.

## Запуск

### Развернуть на Vercel
1. Получи бесплатный ключ в [Google AI Studio](https://aistudio.google.com/app/apikey).
2. Импортируй репозиторий на [vercel.com/new](https://vercel.com/new).
3. Добавь переменную окружения `GEMINI_API_KEY` и сделай Redeploy.

### Запустить локально
```bash
npm i -g vercel
cp .env.example .env.local   # впиши свой ключ
vercel dev
```

Необязательная переменная `GEMINI_MODEL` задаёт модель (по умолчанию `gemini-2.5-flash`).

## Технологии

## Ограничения и планы

- Бесплатный уровень Gemini ограничен по числу запросов.
- Фильтр кода эвристический, в планах добавить вторую проверку ответа отдельным запросом к модели.
- Планируется: интерфейс на казахском, запуск кода в песочнице для реальной трассировки, оценка самостоятельности студента.
